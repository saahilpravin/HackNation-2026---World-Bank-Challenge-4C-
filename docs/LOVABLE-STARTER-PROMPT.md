Build a polished, mobile-first web client called Lauda for a small tourism business operator. Preserve the generated project's framework and routing conventions. This is a port of an existing Expo app's web experience, with an existing Java backend and local model services; do not replace them with cloud AI calls or introduce login/logout.

Use a professional violet, deep plum, mint and restrained coral palette. Keep four easy-to-access tabs: Home, Reviews, Bookings, Insights. Include a secondary Help page and Business/Offline settings. Noor's Coffee Farm is the labeled synthetic demo workspace; the brand is generic Lauda.

The Reviews screen has search, response-status filters and 150 synthetic multilingual review records, some already answered. Model aspect scores are detection scores, not business quality. Add two optional AI reply ideas, short and detailed, generated by the existing local backend. Show provenance: Qwen generated locally versus authored template fallback. Distinguish all processed reviews from reviews with usable aspect findings; never invent an AI business score. Keep suggestions off.

Use the attached API contracts and pure TypeScript validators. Implement persistent local browser storage for reviews, owner edits, approved replies, preferences and generated-result caches. Keep synthetic demo data visibly labeled and separate from real imports. Include cached-first screens and clear unavailable/busy/timeout states. Prepare app-shell offline caching appropriate to the generated framework; do not assume hosting alone provides offline operation.

First build the UI against clearly labeled fixtures, then connect the existing API and run acceptance tests. Do not upload model weights, runtime caches or private reviews. Keep the native Expo app and Java/Python services in their existing repository; this new repository is the web client.
